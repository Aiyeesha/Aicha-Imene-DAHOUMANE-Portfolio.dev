## Problèmes à traiter

### 🔴 Bloquant

#### B-1 — ISR inopérant → TTFB ~1,5–2s sur toutes les routes HTML

- **Cause :** `getLocale()` dans `app/layout.tsx` lit `headers()` → opt dynamique. Le nonce CSP par requête (`proxy.ts`) est incompatible avec le cache CDN Vercel → `Cache-Control: no-store` sur toutes les pages HTML.
- **Fichiers :** `app/layout.tsx`, `middleware/proxy.ts`
- **Impact :** Chaque visiteur paye le coût SSR complet + Supabase (229ms) + Redis (15ms) à chaque rechargement. Aucun bénéfice du CDN Vercel.
- **Solutions possibles :**
  - **Court terme (effort élevé) :** Remplacer le nonce CSP par une **hash-based CSP** (SHA-256 sur les scripts inline statiques). Rend les routes statiques compatibles avec l'ISR.
  - **Moyen terme (roadmap existante) :** Reverse-proxy homelab (Nginx/Caddy) Q4 2026 — met en cache le HTML indépendamment du `Cache-Control` applicatif.
- **Cible :** TTFB < 100ms sur cache HIT.

### 🟠 Majeur

#### M-1 — Slug 404 sur article de blog depuis la homepage

- **URL testée :** `/fr/blog/migration-visualforce-to-lwc` → **404**
- **Probable cause :** Désynchronisation entre le slug affiché dans le preview homepage et le slug réel en base/fichier MDX.
- **Fix :**
  1. Auditer tous les slugs du blog via `SELECT slug FROM articles` (ou équivalent MDX) et comparer avec les URLs générées par `next-intl`.
  2. Ajouter un test E2E Playwright qui parcourt `/fr/blog`, clique sur chaque article listé et vérifie que la réponse HTTP est 200.
  3. Si des slugs ont changé, ajouter des redirects 301 dans `next.config.mjs` → `redirects()`.

```ts
// next.config.mjs — exemple
async redirects() {
  return [
    {
      source: '/fr/blog/migration-visualforce-to-lwc',
      destination: '/fr/blog/<slug-correct>',
      permanent: true,
    },
  ]
}
```

#### M-2 — Projets incomplets visibles publiquement

- **Page :** `/fr/projects`
- **Projets concernés :** `IndusTrak` ("Bientôt"), `CRM Healthcare` ("En cours")
- **Fix :** Vérifier que le filtre Supabase dans `getPublishedProjectsWithAssetsCached()` ne remonte que les projets avec `status = 'published'`. Si ces projets ont un statut différent (`draft`, `wip`) ils ne doivent pas apparaître.

```ts
// lib/data/projects.cached.ts — à vérifier
.eq('status', 'published') // ← doit être présent dans toutes les requêtes publiques
```

#### M-3 — Mentions légales incomplètes (LCEN)

- **Page :** `/fr/legal`
- **Problème :** "SIRET : non applicable (activité en portage salarial)" — la loi exige de mentionner la société de portage (raison sociale, SIRET, adresse).
- **Fix :** Mettre à jour `app/[locale]/legal/page.tsx` (ou le fichier de contenu associé) avec les informations de la société de portage. Si l'activité évolue vers auto-entreprise/SASU, remplacer par le SIRET propre.

#### M-4 — Déclaration d'accessibilité insuffisante

- **Page :** `/fr/accessibility`
- **Manquants :** date d'évaluation, méthode (axe-core, Lighthouse CI), taux estimé de conformité, liste des non-conformités connues.
- **Fix :** Compléter selon le [modèle RGAA 4.1](https://www.numerique.gouv.fr/publications/rgaa-accessibilite/). Le fait qu'axe-core tourne en CI est un argument fort — le documenter publiquement.

#### M-5 — `components/Hero.tsx` est un fichier fantôme

- **Fichier :** `components/Hero.tsx`
- **Problème :** Fichier d'exemple 40 lignes, non utilisé en prod (le vrai hero est `app/[locale]/track-aware-hero.tsx`). Trompeur pour tout lecteur du code.
- **Fix :** `git rm components/Hero.tsx` ou renommer en `Hero.example.tsx` avec un commentaire explicite.
